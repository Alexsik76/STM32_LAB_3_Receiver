# 📡 STM32 NRF24L01+ Receiver

Проєкт приймача на базі STM32F411 з модулем NRF24L01+ для бездротового зв'язку на частоті 2.4 ГГц. Реалізовано з використанням FreeRTOS та архітектури MVC.

## 🔍 Огляд

Цей проєкт є **приймачем** для системи бездротового керування з передавача на базі STM32. Підтримує три режими роботи:

1. **Режим клавіатури** - прийом і відображення натиснутих клавіш
2. **Режим сервоприводів** - керування двома сервоприводами через джойстик
3. **Автоматичний режим** - прийом і відображення текстових повідомлень

### Ключові особливості

- ✅ **RTOS-архітектура** - три окремі задачі для радіо, логіки та дисплея
- ✅ **MVC патерн** - чітке розділення Model (Radio), View (Display), Controller (Logic)
- ✅ **Низьке енергоспоживання** - використання DMA для I2C
- ✅ **Real-time дисплей** - OLED SSD1306 з оновленням екрану без затримок
- ✅ **Безпечне керування сервоприводами** - обмеження діапазону ШІМ для захисту від пошкоджень

## 🔧 Апаратна частина

### Мікроконтролер
- **MCU**: STM32F411CEU6 (Cortex-M4, 100 MHz)
- **Flash**: 512 KB
- **RAM**: 128 KB
- **Тактова частота**: 96 MHz (PLL від HSE)

### Периферія

| Пристрій | Інтерфейс | Піни | Опис |
|----------|-----------|------|------|
| **NRF24L01+** | SPI1 | PA4 (CSN), PA5 (SCK), PA6 (MISO), PA7 (MOSI), PB0 (CE), PB1 (IRQ) | Радіомодуль 2.4 ГГц |
| **SSD1306** | I2C1 (DMA) | PB6 (SCL), PB7 (SDA) | OLED дисплей 128x64 |
| **Сервопривід X** | TIM2_CH1 | PA0 | ШІМ керування (1000-2000 мкс) |
| **Сервопривід Y** | TIM2_CH3 | PA2 | ШІМ керування (1000-2000 мкс) |
| **LED індикація** | GPIO | PC13 | Вбудований LED (активний LOW) |

### Схема підключення

```
STM32F411          NRF24L01+
─────────          ──────────
  PA4  ────────────  CSN
  PA5  ────────────  SCK
  PA6  ────────────  MISO
  PA7  ────────────  MOSI
  PB0  ────────────  CE
  PB1  ────────────  IRQ
  GND  ────────────  GND
 3.3V  ────────────  VCC

STM32F411          SSD1306 OLED
─────────          ────────────
  PB6  ────────────  SCL
  PB7  ────────────  SDA
  GND  ────────────  GND
 3.3V  ────────────  VCC
```

## ⚙️ Функціональність

### 1️⃣ Режим Клавіатури (MODE_KEYPAD)

**Призначення**: Прийом і відображення натиснутих клавіш з матричної клавіатури передавача.

**Протокол пакету**:
```
Byte 0: mode = 0x00 (SystemMode::Keypad)
Byte 1: ASCII код клавіші ('0'-'9', 'A'-'D', '*', '#')
Byte 2-31: не використовуються
```

**Відображення**:
- Верхній рядок: "RX: Mode Keypad"
- Центр екрану: велика літера/цифра

---

### 2️⃣ Режим Сервоприводів (MODE_SERVO)

**Призначення**: Керування двома сервоприводами на основі даних джойстика.

**Протокол пакету**:
```
Byte 0: mode = 0x01 (SystemMode::Servo)
Byte 1: val_x (0-255, позиція джойстика по осі X)
Byte 2: val_y (0-255, позиція джойстика по осі Y)
Byte 3-31: не використовуються
```

**Перетворення даних**:
```cpp
// Вхід: 0..255 → Вихід: 1000..2000 мкс
pulse_x = 1000 + (val_x * 1000 / 255) + SERVO_TRIM_X
pulse_y = 1000 + (val_y * 1000 / 255) + SERVO_TRIM_Y

// Обмеження безпеки
if (pulse < 500)  pulse = 500;   // 0.5 мс мінімум
if (pulse > 2500) pulse = 2500;  // 2.5 мс максимум
```

**Відображення**:
- Верхній рядок: "RX: Servo Ctrl"
- Центр екрану: "X:127 Y:127" (сирі значення 0-255)

**Налаштування триму** (у файлі `logic.hpp`):
```cpp
static constexpr int16_t SERVO_TRIM_X = 0;  // Підберіть експериментально
static constexpr int16_t SERVO_TRIM_Y = 0;  // Діапазон: -500..+500 мкс
```

---

### 3️⃣ Автоматичний режим (MODE_AUTO)

**Призначення**: Прийом і відображення текстових повідомлень.

**Протокол пакету**:
```
Byte 0: mode = 0x02 (SystemMode::Auto)
Byte 1-30: текстовий рядок (null-terminated)
Byte 31: \0
```

**Відображення**:
- Верхній рядок: "RX: Auto Text"
- Центр екрану: отриманий текст

## 🐛 Усунення несправностей

### Проблема: Дисплей не ініціалізується

**Симптоми**: Екран порожній, task `display_task` зупиняється.

**Рішення**:
1. Перевірте підключення I2C (PB6=SCL, PB7=SDA)
2. Виміряйте напругу живлення OLED (має бути 3.3В)
3. Перевірте pull-up резистори на лініях I2C (4.7 кОм)
4. Використайте I2C Scanner для пошуку адреси пристрою

---

### Проблема: Не приходять пакети

**Симптоми**: LED не блимає, черга `radioToLogicQueue` порожня.

**Рішення**:
1. Перевірте живлення NRF24 (3.3В, мінімум 100 мА пікове)
2. Перевірте IRQ пін (PB1) - має бути HIGH у режимі очікування
3. Перевірте співпадіння адрес RX/TX
4. Перевірте канал (має співпадати з передавачем)
5. Додайте decoupling конденсатори (10 мкФ + 100 нФ) біля NRF24

**Діагностика**:
```cpp
// У radio.cpp додайте лог після ініціалізації
uint8_t status = radio.get_status();
uint8_t fifo = radio.get_fifo_status();
// Додайте breakpoint і перевірте значення
```

---

### Проблема: Сервопривід тремтить або не рухається

**Симптоми**: Нестабільне положення серво, дерганий рух.

**Рішення**:
1. **Перевірте живлення серво** (5В окремий BEC, не з STM32!)
2. **Підключіть загальну землю** між STM32 і серво
3. **Налаштуйте trim** значення в `logic.hpp`:
   ```cpp
   static constexpr int16_t SERVO_TRIM_X = -50;  // Приклад
   ```
4. **Перевірте частоту ШІМ** (має бути 50 Гц = 20 мс період)
5. **Виключіть шум на лінії радіо** (використайте екранований кабель)

---

### Проблема: Stack overflow RTOS task

**Симптоми**: HardFault, зависання, reset мікроконтролера.

**Рішення**:
1. Збільшіть розмір стеку в `freertos.c`:
   ```c
   .stack_size = 512 * 4,  // Замість 256 * 4
   ```
2. Перевірте використання heap через FreeRTOS stats
3. Уникайте великих локальних масивів (використовуйте `static` або `malloc`)

## 🔐 Безпека та надійність

### Захист від помилок

1. ✅ **Семафори з timeout** - запобігають deadlock
2. ✅ **Обмеження діапазону ШІМ** - захист сервоприводів від пошкоджень
3. ✅ **Critical sections** - захист HAL стану від race condition
4. ✅ **Null-checks** - перевірка валідності вказівників
5. ✅ **Queue overflow handling** - втрата пакетів замість блокування

### Фіксинг відомих багів

У версії коду реалізовано виправлення:
- **Неправильна ініціалізація семафорів** - виправлено на `initial_count = 0`
- **I2C HAL state race** - додано `taskENTER_CRITICAL()` при модифікації
- **Deadlock LED blink** - блимання тільки при успішній передачі в чергу
